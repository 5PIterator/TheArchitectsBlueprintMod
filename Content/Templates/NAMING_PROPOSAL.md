# Naming Convention Proposal

## ITR Convention

**ITR** = short for Interaction / InteractionMap. Prefix/suffix for scripts that work with `.itr` JSON map files.

| Script / Class | ITR name | Role |
|----------------|----------|------|
| `ITRStorage` | `ItrStorage` | Loads compiled .itr at paste time |
| `ItrFileProcessor` | ✓ already | Low-level .itr parsing |
| `ItemMapLoader` | `ItrLoader` | Loads source .itr into InteractionMap |
| `TileMapCompiler` | `ItrCompiler` | Compiles to .itr layer files |

Use **Itr** prefix for types that directly read/write the .itr format. Domain types (`InteractionMap`, `InteractionEntry`) stay as-is.

---

## Current State

The system uses **InteractionMap** as the unified concept: a dual-indexed map of item↔tile/wall/liquid interactions. The confusion comes from naming that doesn't reflect this:

| Term | What it actually is | Issue |
|------|----------------------|-------|
| **TileMap** | InteractionMap with tile-first format (main key = tile/wall/liquid) | "Tile" suggests only tiles; compiled maps include Wall, Liquid, Wire, Paint |
| **ItemMap** | InteractionMap with item-first format (item key = item name) | "ItemMap" used for both the format and the directory, which holds mixed formats |
| **ItemMaps** (dir) | Source directory: discovery output + editable config | Contains Placement.itr (tile-first) and Biome.itr (item-first) — not "item-only" |
| **TileMaps** (dir) | Compiled directory: tile-first layer files for paste | Correct format, but "Tile" undersells that it includes all layers |
| **mapType "tilemap"** | Metadata for compiled layer files | Overloaded with directory name; vague |

---

## Proposed Naming Scheme

Tie everything to **InteractionMap** and distinguish by **format** (item-first vs tile-first) and **pipeline stage** (source vs compiled).

### 1. Directories

| Current | Proposed | Rationale |
|---------|----------|-----------|
| `ItemMaps` | `SourceMaps` | Holds discovery output and editable config; mixed formats. "Source" = input to compile. |
| `TileMaps` | `CompiledMaps` | Holds tile-first layer files generated by compile; used at paste time. |

**Alternative (format-focused):** Keep `ItemMaps` / `TileMaps` if you prefer not to change user-facing paths. The inconsistency is that ItemMaps contains tile-first Placement.itr.

### 2. mapType Value

| Current | Proposed | Rationale |
|---------|----------|-----------|
| `"tilemap"` | `"compiled"` | Unambiguous; describes purpose (compiled for paste) not format. |

### 3. Class / Method Names

| Current | Proposed | Rationale |
|---------|----------|-----------|
| `ItemMapLoader` | `ItrLoader` | Loads source .itr into InteractionMap (ITR convention). |
| `TileMapCompiler` | `ItrCompiler` | Compiles to .itr layer files (ITR convention). |
| `GetItemMapsDirectory()` | `GetSourceMapsDirectory()` | If directory renamed. |
| `GetItemMapPath()` | `GetSourceMapPath()` | If directory renamed. |
| `GetTileMapsDirectory()` | `GetCompiledMapsDirectory()` | If directory renamed. |
| `GetTileMapPath()` | `GetCompiledMapPath()` | If directory renamed. |

**Keep as-is:** `TileFirstMap`, `ItemFirstMap`, `InteractionMap`, `InteractionEntry` — these are already clear.

### 4. Namespace

`TileMapping` can stay — it describes the domain (mapping tiles/walls to items). Alternative: `InteractionMapping` if you want full consistency with "InteractionMap".

## Summary of Changes (if adopting)

1. **Directories:** `ItemMaps` → `SourceMaps`, `TileMaps` → `CompiledMaps` ✓
2. **mapType:** `"tilemap"` → `"compiled"` ✓
3. **Classes:** `ItemMapLoader` → `ItrLoader` ✓, `TileMapCompiler` → `ItrCompiler` ✓
4. **Methods:** `GetItemMapsDirectory` → `GetSourceMapsDirectory`, etc. ✓
5. **Constants:** `ItemMapsDir` → `SourceMapsDir`, `TileMapsDir` → `CompiledMapsDir` ✓
6. **Template paths:** `Content/Templates/ItemMaps/` → `Content/Templates/SourceMaps/` ✓
7. **Docs:** Update INTERACTION_MAPS_TUTORIAL.md to use new terms ✓

## Minimal-Change Option

If you want to avoid path changes:

1. Rename **mapType** `"tilemap"` → `"compiled"` (code + new output only)
2. Rename **ItemMapLoader** → **ItrLoader** ✓
3. Rename **TileMapCompiler** → **ItrCompiler** ✓
4. Update docs to clarify: "ItemMaps = source directory (mixed formats), TileMaps = compiled tile-first directory"

This improves code clarity without touching user-facing paths.
