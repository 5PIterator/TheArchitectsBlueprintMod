# Interaction Maps Tutorial

Interaction maps tell The Architect's Blueprint mod which items can create or modify tiles, walls, liquids, wires, and paint. This guide explains how to edit them and what each value means.

---

## File Structure

All SourceMaps are JSON files with the **`.itr.json`** extension and a **metadata + data wrapper**:

```json
{
  "metadata": {
    "format": "tile-first" | "item-first",
    "mapType": "placement" | "biome" | "custom" | "biomeConfig" | "baseContext" | "compiled" | "shimmer" | "wand" | "rubble",
    "modVersion": "...",
    "terrariaVersion": "...",
    "generatedAt": "2025-02-28T..."
  },
  "data": { ... }
}
```

The `metadata` identifies the file by content (format, mapType). The `data` object holds the actual content. All interaction maps use this structure and are found by metadata.

---

## File Locations

| File | Directory | Purpose | Format | Editable? |
|------|-----------|---------|--------|-----------|
| `Custom.itr.json` | SourceMaps | Curated item→tile interactions | Item-first | Yes |
| `BiomeConfig.itr.json` | SourceMaps | Biome conversion items (type, yield) for BiomeDiscovery | Item-first | Yes |
| `BaseContext.itr.json` | SourceMaps | Tile names for placement discovery fallback | Item-first | Yes |
| `Placement.itr.json` | SourceMaps | Discovered direct placements (from `/tab.discPlace`) | Tile-first | No (generated) |
| `Wands.itr.json` | SourceMaps | Discovered wand/ammo tools (from `/tab.discWand`) | Item-first | No (generated) |
| `Rubble.itr.json` | SourceMaps | Discovered FlexibleTileWand / Rubblemaker options (from `/tab.discRubble`) | Item-first | No (generated) |
| `Biome.itr.json` | SourceMaps | Discovered biome conversions (from `/tab.discBiome`) | Item-first | No (generated) |
| `Shimmer.itr.json` | SourceMaps | Discovered shimmer transforms (from `/tab.discShimmer`) | Item-first | No (generated) |
| `InteractionMap.itr` / `.itr.json` | CompiledMaps | Compiled maps used at paste time | Tile-first | No (generated) |

- **SourceMaps** (`TheArchitectsBlueprintMod\SourceMaps\`): Discovery output and editable config. Templates are copied here on first launch.
- **CompiledMaps** (`TheArchitectsBlueprintMod\CompiledMaps\`): Compiled layer maps. Generated by `/tab.compile`.

## Unified Interaction Format

All interaction maps use the **same per-interaction fields**. The only difference is whether the map is **item-first** or **tile-first**:

| Map type | Key | Interaction fields |
|----------|-----|--------------------|
| **Item-first** | Item name | `layer`, `main`, `base`, `style`, `yield`, `ammo` |
| **Tile-first** | Tile/wall/liquid name | `layer`, `item`, `base`, `style`, `yield`, `ammo` |

In tile-first maps, the main result is the key (the tile being described). Each interaction specifies `layer` to interpret the main. In item-first maps, the item is the key, so each interaction specifies `layer` and `main` (the result).

---

### Per-interaction fields

| Field | Required | Description |
|-------|----------|-------------|
| `layer` | Yes | `"Tile"` \| `"Wall"` \| `"Liquid"` \| `"Wire"` \| `"Paint"` |
| `main` | Yes (item-first) | Resulting tile, wall, liquid, wire, or paint. |
| `item` | Yes (tile-first) | The item that can create this tile/wall/liquid. |
| `base` | No | Source tile/wall the item must interact with. Omit for direct placement. |
| `style` | No | Placement style for direct placement (e.g. torch variant). -1 for terrain or style-agnostic. |
| `yield` | No | Interactions per item. `1` = one block. `null` = infinite. |
| `ammo` | No | The item to be consumed instead of the main 'item'. |
| `alias` | No | Alternate tool item names accepted when the primary item is missing (e.g. Rubblemaker modes). |
| `fake` | No | Tile/wall actually placed when different from `main` (e.g. Echo rubble for a natural ambient main). |

Missing fields are skipped at load time and logged. Check the compile debug log if entries are missing.

Each layer interprets `base` and `main` differently:
- **Tile**: `base` = source tile, `main` = result tile
- **Wall**: `base` = source wall, `main` = result wall
- **Liquid**: `main` = result liquid type
- **Wire**: `main` = result wire kind
- **Paint**: `main` = result paint ID

### itemInteractions (Item-first)

Keys are **item internal names** (e.g. `"CorruptSeeds"`, `"WaterBucket"`). Each item has an `interactions` array.

#### Examples

**Seed (converts existing tile):**
```json
"CorruptSeeds": {
  "interactions": [
    {
      "layer": "Tile",
      "base": "Dirt",
      "main": "CorruptGrass",
      "yield": 1
    }
  ]
}
```

**Bucket (direct placement):**
```json
"WaterBucket": {
  "interactions": [
    {
      "layer": "Liquid",
      "main": "Water",
      "yield": 10 // instead of full tiles, this layer uses liquid level of a tile
    }
  ]
}
```

**Tool with ammo (e.g. Living Wood Wand):**
```json
"LivingWoodWand": {
  "interactions": [
    {
      "layer": "Tile",
      "main": "LivingWood",
      "yield": 1,
      "ammo": "Wood"
    }
  ]
}
```

**Rubblemaker with tool alias and Echo fake:**
```json
"Rubblemaker": {
  "interactions": [
    {
      "layer": "Tile",
      "main": "SmallPiles",
      "fake": "SmallPiles1x1Echo",
      "style": 0,
      "yield": 1,
      "ammo": "StoneBlock",
      "alias": ["RubblemakerMedium", "RubblemakerLarge"]
    },
    {
      "layer": "Tile",
      "main": "SmallPiles1x1Echo",
      "style": 0,
      "yield": 1,
      "ammo": "StoneBlock",
      "alias": ["RubblemakerMedium", "RubblemakerLarge"]
    }
  ]
}
```

Lookup uses `main`; placement uses `fake` when set. `alias` lists alternate tool item types that also satisfy the tool (Rubblemaker size modes).
      "yield": 1,
      "ammo": "Wood"
    }
  ]
}
```

### Tile Maps (Tile-first, generated)

Keys are **tile/wall/liquid names** (e.g. `"Dirt"`, `"Stone"`). Each entry has an `interactions` array:

```json
"Dirt": {
  "interactions": [
    {
      "layer": "Tile",
      "Item": "DirtBlock",
      "base": null,
      "style": 0,
      "yield": null,
      "ammo": null
    }
  ]
}
```

For compact `itemNames` format, `layer` is at the value level:

```json
"StoneWall": {
  "layer": "Wall",
  "itemNames": ["StoneWall", "WoodWall"]
}
```

### BiomeConfig.itr.json (mapType=biomeConfig)

Configures items used by **BiomeDiscovery** (run `/tab.discBiome` to generate `Biome.itr.json`). The `data` object has item names as keys; values have:

| Field | Description |
|-------|-------------|
| `type` | BiomeConversionID: `0`=Purity, `1`=Corruption, `2`=Hallow, `3`=GlowingMushroom, `4`=Crimson, `5`=Sand, `6`=Snow, `7`=Dirt, `8`=PurificationPowder, `10`=Chlorophyte |
| `yield` | Blocks converted per item (e.g. `5` for powder, `50` for solution) |

Keys use **internal names** (e.g. `GreenSolution`, not "Green Solution"):

```json
"GreenSolution": { "type": 0, "yield": 50 }
```

---

### BaseContext.itr.json (mapType=baseContext)

Array of tile names used as fallback for **placement discovery**. The `data` array lists tiles to test when an item's `createTile` requires a base (e.g. seeds on dirt). Add tiles commonly used as conversion targets:

```json
{
  "metadata": { "format": "item-first", "mapType": "baseContext" },
  "data": ["Dirt", "Mud", "Stone", "Ash", "GrayBrick"]
}
```

---

## Name Resolution

- **Item names**: Use internal names (e.g. `WaterBucket`, `PurificationPowder`, `GreenSolution`) or `ModName/ItemName` for modded items.
- **Tile/wall names**: Use internal names (e.g. `"Dirt"`, `"CorruptGrass"`). Vanilla names are in the template; modded tiles use `ModName/TileName`.

Unresolved names are skipped at load time and logged. Check the compile debug log if entries are missing.

---

## Workflow

1. Edit `Custom.itr.json`, `BiomeConfig.itr.json`, and `BaseContext.itr.json` in `TheArchitectsBlueprintMod\SourceMaps\` (copied from templates on first launch).
2. Run `/tab.discPlace` to regenerate placement interactions (if you changed Custom or BaseContext).
3. Run `/tab.discBiome` to regenerate biome conversions (if you changed BiomeConfig).
4. Run `/tab.discShimmer` to regenerate shimmer transforms.
5. Run `/tab.compile` to rebuild the tile maps used by the mod.

Or run `/tab.discAll` to run all discovery commands, then `/tab.compile` to compile.
